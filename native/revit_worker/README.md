# BIMAP Native Revit Worker

This directory implements the native Autodesk Revit boundary already consumed by `applications/bimap/revit_backend.py` (or the equivalent deployment module in the host SLAI checkout). The Python side remains provider-neutral: it invokes one executable through the existing `inspect`, `extract`, `convert`, and `preview` CLI contract. The executable is a broker; the Autodesk Revit API code runs only inside an APS Automation AppBundle.

## Architecture

```text
BIMAP Python backend
    |
    | BIMAP_REVIT_EXTRACTOR_EXECUTABLE
    v
Bimap.RevitWorker.Broker.exe
    |
    | OAuth + OSS + APS Automation WorkItem
    v
BimapRevitWorkerActivity (Autodesk.Revit+2026)
    |
    v
Bimap.RevitWorker.AppBundle
    |
    +-- inspect  -> result JSON
    +-- extract  -> canonical BIMAP extraction JSON
    +-- convert  -> glTF 2.0 binary (.glb bytes)
    +-- preview  -> PNG bytes
```

There is no assembly reference from the broker to the AppBundle and no reference from the AppBundle back to the broker. Their only shared contract is `params.json` plus the APS Activity input/output parameter names. This is intentional: it prevents a circular dependency and keeps Autodesk Revit assemblies out of the BIMAP web/backend process.

## Source layout

- `Bimap.RevitWorker.Broker/`: .NET 8 Windows CLI broker. `dotnet publish` produces `Bimap.RevitWorker.Broker.exe`.
- `Bimap.RevitWorker.AppBundle/`: Revit 2026 Design Automation DBApplication.
- `activity.template.json`: APS Activity definition template.
- `build.ps1`: builds the DLL/AppBundle ZIP and publishes the standalone broker executable.

## Prerequisites

1. .NET 8 SDK on the Windows build machine.
2. An Autodesk Platform Services application with Automation access.
3. An APS AppBundle named `BimapRevitWorker` (recommended alias: `prod`) containing `dist/BimapRevitWorker.AppBundle.zip`.
4. An APS Activity based on `activity.template.json`, using engine `Autodesk.Revit+2026` and the AppBundle alias above.
5. The fully-qualified Activity alias, for example `yourNickname.BimapRevitWorkerActivity+prod`.

The AppBundle project references Autodesk's Revit 2026 Design Automation/Revit API packages and deliberately excludes those assemblies from runtime packaging because the APS Revit engine supplies them.

## Build

From PowerShell:

```powershell
cd applications\bimap\native\revit_worker
.\build.ps1
```

Build outputs:

```text
dist/
├── broker/
│   └── Bimap.RevitWorker.Broker.exe
├── BimapRevitWorker.bundle/
└── BimapRevitWorker.AppBundle.zip
```

`Bimap.RevitWorker.Broker.exe` is a generated binary and therefore is not stored as hand-written source. Do not create or commit a fake executable placeholder.

## APS runtime configuration

Configure the host process that starts BIMAP:

```powershell
$env:APS_CLIENT_ID="<APS client id>"
$env:APS_CLIENT_SECRET="<APS client secret>"
$env:BIMAP_APS_DA_ACTIVITY_ID="<nickname>.BimapRevitWorkerActivity+prod"

# Optional. If omitted, the broker derives a deterministic private bucket key
# from the client id.
$env:BIMAP_APS_OSS_BUCKET_KEY="<globally unique lowercase APS bucket key>"

$env:BIMAP_APS_DA_TIMEOUT_SECONDS="600"
$env:BIMAP_APS_DA_POLL_SECONDS="3"
$env:BIMAP_REVIT_WORKER_MAX_SOURCE_BYTES="536870912"
$env:BIMAP_REVIT_WORKER_MAX_OUTPUT_BYTES="268435456"

$env:BIMAP_REVIT_EXTRACTOR_EXECUTABLE="G:\GAIA\AI\SLAI\applications\bimap\native\revit_worker\dist\broker\Bimap.RevitWorker.Broker.exe"
$env:BIMAP_REVIT_EXTRACTOR_TIMEOUT_SECONDS="650"
```

The Python timeout should be slightly greater than the broker timeout so the broker can cancel/fail its own remote operation before BIMAP kills the process.

Never put APS credentials into `bimap.yaml`, source control, frontend environment files, audit JSON, or log payloads.

## APS Activity

Replace `__APS_NICKNAME__` in `activity.template.json` with the APS nickname that owns the AppBundle. Publish the Activity with an alias such as `prod`, then set `BIMAP_APS_DA_ACTIVITY_ID` to the fully-qualified Activity alias.

The Activity uses three stable arguments:

- `inputFile`: source RFA/RVT, downloaded by APS with the original object name.
- `inputJson`: `params.json`, generated by the broker.
- `outputFile`: `result.bin`, uploaded by APS. The bytes are JSON, GLB, or PNG depending on the requested mode; the broker validates them and writes them to the exact `--output` path supplied by BIMAP.

## CLI contract

The broker exactly matches the current BIMAP native-worker boundary:

```text
Bimap.RevitWorker.Broker.exe --mode inspect  --input <file.rfa> --source-format rfa --output <result.json>
Bimap.RevitWorker.Broker.exe --mode extract  --input <file.rfa> --source-format rfa --output <result.json> --datasets elements,properties,quantities,materials
Bimap.RevitWorker.Broker.exe --mode convert  --input <file.rfa> --source-format rfa --target-format glb --output-stem model --output <artifact.glb>
Bimap.RevitWorker.Broker.exe --mode preview  --input <file.rfa> --source-format rfa --output <preview.png>
```

The same modes support RVT where the BIMAP caller advertises them. `extensions.revit_family` is emitted only for RFA/family documents, preserving the existing Python validation rule.

## GLB identity contract

Each exported Revit element is written as a glTF node with:

```text
node.name                 = Element.UniqueId
node.extras.elementId     = Element.Id.Value
node.extras.revitId       = Element.Id.Value
node.extras.uniqueId      = Element.UniqueId
node.extras.category      = Revit category name
node.extras.typeName      = Revit type name
```

This matches the current BIMAP `BIMModelViewer.tsx` indexing strategy. No Three.js/viewer modification is required for model loading or element alias resolution.

## Geometry conventions

Revit internal geometry is converted from feet to metres. Coordinates are mapped from Revit's right-handed Z-up system to glTF's right-handed Y-up system as `(X, Y, Z) -> (X, Z, -Y)`. Solids are triangulated using the Revit API. GLB indices use unsigned 32-bit values. Materials use Revit base color and transparency with a conservative metallic/roughness approximation.

Geometry summary fields generated by the native worker are:

```text
total_polygons
total_vertices
total_unique_edges
volume              # cubic metres
watertight_geometries
```

Watertightness is a topology signal: after positional quantization, every undirected mesh edge must be used by exactly two triangles.

## Failure behavior

The broker fails closed. It validates CLI arguments, APS configuration, HTTP outcomes, work-item state, maximum output size, and the returned artifact signature. It does not return PartAtom data when a native job fails and it does not fabricate geometry or preview images.

The AppBundle does not log customer evidence or model paths. Errors emitted to the APS job report are bounded to error type and sanitized message text.

## Version policy

The supplied project is intentionally pinned to Revit/APS 2026 packages and `Autodesk.Revit+2026`. Upgrade Revit engine, Design Automation Revit package, Revit API package, `PackageContents.xml`, and the Activity together. Do not silently run a 2026-built AppBundle under a different Revit engine generation.
